# 项目版本演进记录

本文档用于记录考研督学网站几个关键版本中的最大改动，方便以后回顾项目是怎么一步步从本地原型走向真实可用系统的。

当前记录日期：2026-06-17

## 版本总览

| 版本 | 阶段定位 | 最大变化 |
| --- | --- | --- |
| V1 | 本地验证原型 | 先把页面和核心想法在本地跑通，验证“学生端督学网站”这件事是否可行 |
| V2 | 服务器与手机网页修正 | 后端服务跑起来，网页可以通过服务访问，并把页面重点修正为手机端体验 |
| V3 | 当前版本：真实数据/API 与五页面结构化 | 从静态页面升级为数据库/API 驱动，完成学生登录到反馈、自习、排行、曲线、我的页面的完整闭环，并做前端拆分和文档化 |

## V1：本地验证原型

### 阶段目标

V1 的目标不是正式上线，而是先验证这个产品方向是否成立：

```text
能不能用一个学生端网页，把考研数学督学的核心流程展示出来？
```

### 最大改动

1. 建立了学生端手机网页的初始视觉原型。
2. 用本地静态数据展示主要页面内容。
3. 初步确定学生端需要围绕几个核心页面展开：
   - 今日计划
   - 排行
   - 曲线
   - 自习室
   - 我的
4. 先验证页面样式、信息层级、学习流程是否合理。

### 为什么重要

这个版本解决的是“产品有没有形”的问题。

在这个阶段，重点不是数据库、接口、多人并发，而是先看：

- 页面是否适合考研学生使用。
- 每天学习任务能不能被清楚表达。
- 排行和曲线是否有激励与诊断价值。
- 自习室是否能让学生进入专注状态。

### 当时的局限

1. 数据主要是静态写死的。
2. 页面和业务逻辑没有真正连接数据库。
3. 登录不同学生账号时，个性化能力有限。
4. 还不是正式服务器访问形态。
5. 更像“可交互原型”，不是完整真实系统。

## V2：服务器与手机网页修正

### 阶段目标

V2 的目标是让网页从“本地文件/本地原型”向“可以通过后端服务访问”的方向前进一步：

```text
能不能通过服务器地址打开，并让手机端网页看起来更像真实产品？
```

### 最大改动

1. 增加 FastAPI 后端服务。
2. 网页可以通过 `http://127.0.0.1:8000/` 访问。
3. 开始处理手机访问问题，例如局域网访问、热点访问、电脑 IP 访问。
4. 明确这是一个手机端网页，不是桌面端网站。
5. 对手机端页面格式、排版、视觉风格做了多轮修正。
6. 开始围绕真实使用场景修正页面：
   - 登录界面要适合学生账号验证。
   - 到期账号登录后提示到期。
   - 停用账号不允许登录。
   - 页面要更清新，更适合考研学生。

### 为什么重要

这个版本解决的是“产品能不能被真实打开和体验”的问题。

V1 主要验证页面想法，V2 开始验证运行方式：

- 后端服务能不能启动。
- 浏览器能不能打开。
- 手机端能不能测试。
- 页面是不是按手机屏幕设计。
- 登录和账号状态是否开始具备真实产品逻辑。

### 当时的局限

1. 数据和 API 还不够完整。
2. 手机访问受网络环境影响较大。
3. 很多页面还保留静态或半静态逻辑。
4. 业务闭环还没有完全打通。
5. 页面代码仍然比较集中，后续维护压力开始出现。

## V3：当前版本，真实数据/API 与五页面结构化

### 阶段目标

V3 的目标是把网站从“看起来像”推进到“数据真的能跑起来”：

```text
一个学生能否从登录开始，看到自己的今日计划，完成学习与反馈，并让排行、曲线、自习室、我的页面跟着真实数据变化？
```

### 最大改动

#### 1. 从静态数据升级为真实数据库/API

当前已经建立了 SQLite 数据库和一批 Excel 样本表。

主要数据表包括：

- `users.xlsx`
- `student_profiles.xlsx`
- `classes.xlsx`
- `question_types.xlsx`
- `questions.xlsx`
- `daily_plans.xlsx`
- `question_feedbacks.xlsx`
- `student_progress.xlsx`
- `student_daily_activity.xlsx`
- `type_mastery_stats.xlsx`
- `loss_reason_stats.xlsx`
- `focus_sessions.xlsx`
- `institutions.xlsx`

这些表让网站不再只是展示固定页面，而是开始具备真实数据结构。

#### 2. 打通学生登录到提交反馈的闭环

当前学生登录后，会请求自己的五类数据：

- 今日计划
- 排行
- 曲线
- 自习室
- 我的页面

学生可以在今日计划页提交反馈，提交后前端会重新请求相关数据，让页面状态发生变化。

#### 3. 建立 `student_progress` 进度表

这是当前版本非常关键的业务设计。

它让系统能够记录每个学生当前布置到哪里了，而不是每次都从头开始。

这为后续实现“按题型顺序、按章节顺序、按学生进度持续布置任务”打下基础。

#### 4. 题型表升级

题型表根据更完整的题型分类进行了升级，并补充了线代章节：

- 线代第一章 行列式
- 线代第二章 矩阵
- 线代第三章 向量
- 线代第四章 线性方程组
- 线代第五章 特征值与特征向量
- 线代第六章 二次型

这让曲线页的章节掌握度更完整，也让未来布置题目更有结构。

#### 5. 今日计划页升级

今日计划页不再只是静态页面，而是由 API 驱动。

关键能力包括：

- 根据学生账号加载今日计划。
- 展示今日题型。
- 按题目提交正确、错误、未作反馈。
- 完成全部题型后显示鼓励文案。
- 到期账号登录后在今日计划提示已到期。
- 停用账号不允许登录。

#### 6. 排行页升级

排行页按照参考图进行了重做，并开始体现班级维度。

关键能力包括：

- 今日打卡榜。
- 本周完成榜。
- 连续坚持榜。
- 勋章墙。
- 下一枚勋章目标。
- 当学生排在十几名时，可以显示前几名、省略中间、再显示自己前后一名。

#### 7. 曲线页升级

曲线页开始使用用户个人数据。

关键能力包括：

- 最近 14 天学习热力图。
- 热力图不包含今天，只显示距离今天的前 14 天。
- 累计自习、最高单日、连续学习基于用户数据。
- 章节掌握度列出所有章节，没做过默认 0%。
- 失分原因比例支持 0% 灰色图、低占比隐藏百分比。
- 最该优先补强内容优先来自低得分率题型。

#### 8. 自习室页升级

自习室页从静态展示变成了可操作的专注功能。

关键能力包括：

- 30、45、60、自定义专注时长。
- 当前任务来自今日计划题型。
- 开始专注后进入沉浸式专注页面。
- 支持暂停、继续、退出专注。
- 退出后结算专注时间。
- 同桌陪伴按班级今日专注时长展示。
- 今日数学学习目标默认 3 小时。

#### 9. 我的页面新增

我的页面根据参考图制作，并删除了不需要的模块。

当前保留：

- 用户名。
- 数学类型。
- 距考研天数。
- 连续学习天数。
- 今日累计学习。
- 我的备考配置。
- 目标院校选择。
- 每日数学学习目标。

同时新增院校表和院校搜索接口，目标院校可以更新到学生数据里。

#### 10. 前端完成一次保持功能不变的拆分

原本前端主要集中在一个很大的 `index.html` 中。

当前已拆分为：

- `index.html`
- `styles/app.css`
- `assets/js/app.js`
- `assets/js/pages/plan.js`
- `assets/js/pages/rank.js`
- `assets/js/pages/curve.js`
- `assets/js/pages/study-room.js`
- `assets/js/pages/profile.js`

这让后续改页面更容易定位问题。

#### 11. 增加项目文档

当前已经新增多份管理文档：

- `docs/project-code-map-and-maintenance.md`
- `docs/five-page-logic-and-roadmap.md`
- `docs/version-history.md`

这些文档的目的，是让不熟悉代码的人也能回顾项目结构、页面逻辑和版本变化。

### 为什么重要

V3 是从“原型”向“MVP 系统”迈出的一步。

这个版本开始解决：

- 数据是否真实。
- 页面是否能根据不同学生变化。
- 提交反馈是否能影响后续状态。
- 自习室是否能记录真实学习行为。
- 排行和曲线是否能使用个人和班级数据。
- 代码是否开始具备后续维护能力。

### 当前仍然存在的局限

1. 还没有正式生产级数据库，例如 PostgreSQL 或 MySQL。
2. 还没有正式用户认证，例如 token、权限隔离、密码加密。
3. Excel 仍然是主要数据维护方式，适合 MVP，但不适合长期多人管理。
4. 还没有教师端或运营后台。
5. 前端虽然已拆分，但仍是原生 HTML/CSS/JS，复杂后可以考虑 Vue 或 React。
6. 手机访问还依赖本地网络环境，正式上线需要云服务器、域名和 HTTPS。
7. 数据计算逻辑还可以继续自动化，例如掌握度、错因、补强推荐。

## 下一版本建议：V4 可以做什么

如果继续往“上万人真实使用”推进，V4 建议优先做：

1. 正式数据库设计
   - 从 Excel + SQLite 逐步迁移到更稳定的数据库。
   - 明确学生、班级、题型、题目、计划、反馈、专注记录之间的关系。

2. 管理后台
   - 学生管理。
   - 班级管理。
   - 题型/题目管理。
   - 每日计划查看与调整。
   - 学习数据查看。

3. 认证和权限
   - 密码加密。
   - 登录 token。
   - 学生只能看自己的数据。
   - 老师只能看自己班级的数据。

4. 数据自动化
   - 提交反馈后自动更新掌握度。
   - 专注结束后自动更新每日学习时长。
   - 今日任务完成后自动推进学生进度。
   - 自动生成最该补强内容。

5. 正式手机端体验
   - 更稳定的手机端适配。
   - 真机测试清单。
   - 页面加载速度优化。
   - 异常状态提示优化。

## 如何维护本文档

每次项目出现“阶段性变化”时，都应该更新本文档。

适合记录到本文档的变化包括：

1. 新增一个大版本。
2. 某个版本完成了关键闭环。
3. 技术路线明显变化。
4. 从本地环境迁移到服务器。
5. 从静态数据迁移到真实数据库。
6. 新增管理后台、教师端、正式认证等大模块。

更新方式：

1. 在“版本总览”表格新增一行。
2. 新增一个版本小节，例如 `V4：正式数据库与管理后台`。
3. 写清楚这个版本的：
   - 阶段目标。
   - 最大改动。
   - 为什么重要。
   - 当前局限。
4. 如果下一版本建议变化，也同步修改“下一版本建议”。
5. 在文档顶部更新“当前记录日期”。
