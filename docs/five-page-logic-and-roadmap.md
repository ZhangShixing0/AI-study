# 五个页面功能逻辑与未来发展指南

本文档用于帮助你随时回顾当前学生端五个页面的功能、数据逻辑、页面之间的关系，以及以后可以如何继续升级。

如果你只想知道“某个文件在哪里”，请看 `docs/project-code-map-and-maintenance.md`。  
如果你想知道“这个页面为什么这样设计、功能是怎么跑起来的、以后还能怎么改”，请看本文档。

## 1. 五个页面的整体关系

当前学生端登录后有五个主页面：

| 页面 | 核心作用 | 对学生的意义 |
| --- | --- | --- |
| 今日计划 | 告诉学生今天做什么题型，并提交做题反馈 | 让学生每天知道具体任务，而不是泛泛地“去学习” |
| 排行 | 展示班级内打卡、完成、本周坚持、连续坚持情况 | 用轻量竞争和勋章激励学生持续学习 |
| 曲线 | 展示个人能力变化、学习热力、章节掌握、失分原因 | 让学生知道自己哪里弱、下一步补什么 |
| 自习室 | 选择当前任务并进入专注计时 | 把“计划”变成真实学习时间 |
| 我的 | 展示个人学习档案和备考配置 | 让学生确认自己的账号、班级、目标、题册等信息 |

这五个页面不是孤立的，它们围绕一个完整学习闭环：

```text
登录学生账号
  ↓
读取该学生的今日计划、排行、曲线、自习室、个人档案
  ↓
今日计划告诉学生今天做哪些题型
  ↓
自习室让学生围绕今日题型进行专注学习
  ↓
学生提交题型反馈
  ↓
后端更新反馈、进度、排行、曲线、自习室数据
  ↓
排行页产生激励，曲线页给出薄弱点，我的页面沉淀个人档案
```

## 2. 登录后的数据加载逻辑

登录入口在前端 `assets/js/app.js` 中。

学生输入账号密码后，前端会调用：

```text
POST /auth/login
```

登录成功后，前端会一次性请求五个页面所需数据：

```text
GET /students/{user_id}/daily-plan
GET /students/{user_id}/rankings
GET /students/{user_id}/curve
GET /students/{user_id}/study-room
GET /students/{user_id}/profile
```

这样做的好处是：登录成功后五个页面可以立即切换，不需要每点一个页面再慢慢加载。

当前前端全局保存了这些数据：

| 前端状态 | 对应数据 |
| --- | --- |
| `activeData` | 今日计划 |
| `activeRankings` | 排行 |
| `activeCurve` | 曲线 |
| `activeStudyRoom` | 自习室 |
| `activeProfile` | 我的 |
| `activeUser` | 当前登录学生 |

## 3. 页面一：今日计划

### 3.1 页面目标

今日计划页的核心目标是回答学生每天最关心的问题：

```text
我今天具体要做什么？
做完以后怎么反馈？
反馈以后下一步是什么？
```

### 3.2 当前显示内容

今日计划页当前主要显示：

- 今日日期、距离考研天数、计划状态。
- 今日需要完成的题型卡片。
- 每个题型对应的习题来源。
- 当前开放反馈的题目列表。
- 正确、错误、未作三个反馈选项。
- 提交本题型反馈按钮。
- 已到期账号提示。
- 今日全部完成后的鼓励文案。

### 3.3 数据来源

主要接口：

```text
GET /students/{user_id}/daily-plan
POST /feedback/submit
```

主要数据表：

| 数据表 | 用途 |
| --- | --- |
| `users.xlsx` | 判断账号是否可登录、是否停用 |
| `student_profiles.xlsx` | 学生所属班级、数学类型、目标分等 |
| `daily_plans.xlsx` | 今日计划记录 |
| `question_types.xlsx` | 题型顺序、章节、题型名称 |
| `questions.xlsx` | 题目列表 |
| `question_feedbacks.xlsx` | 学生提交的反馈 |
| `student_progress.xlsx` | 学生当前布置到哪里 |
| `system_messages.xlsx` | 今日完成后的鼓励文案 |

### 3.4 功能实现逻辑

今日计划的后端逻辑大致是：

1. 根据登录学生 `user_id` 找到学生档案。
2. 判断账号状态：
   - 停用账号不允许登录。
   - 到期账号可以登录，但今日计划页提示已到期。
3. 根据学生班级、数学类型、进度指针，生成或读取今日计划。
4. 按题型顺序展示任务。
5. 找到当前开放反馈的题型。
6. 学生提交反馈后，写入 `question_feedbacks`。
7. 如果本题型完成，后端决定是否打开下一个题型。
8. 如果所有题型完成，返回可配置的完成鼓励语。

前端逻辑大致是：

1. `app.js` 请求今日计划接口。
2. `plan.js` 把今日计划数据渲染成页面。
3. 学生点击正确、错误、未作。
4. `app.js` 收集答案并提交 `/feedback/submit`。
5. 提交成功后，重新请求今日计划、排行、曲线、自习室数据。
6. 页面显示新的状态。

### 3.5 与其他页面的关系

| 关联页面 | 关系 |
| --- | --- |
| 自习室 | 自习室当前任务来自今日计划题型 |
| 排行 | 提交反馈后可能影响今日打卡榜、本周完成榜 |
| 曲线 | 反馈结果会影响正确率、章节掌握度、失分原因 |
| 我的 | 今日累计学习、连续学习等数据会沉淀到个人档案 |

### 3.6 未来升级方向

优先级较高：

- 把“题型讲解图片”升级成真实讲解视频或图文讲义。
- 每道题支持更细的反馈，例如不会原因、耗时、是否看解析。
- 反馈提交后自动生成错题复盘任务。
- 今日计划根据学生能力动态调整任务量。

中长期方向：

- 做教师端或运营后台，可以手动调整某个学生今日任务。
- 支持不同班型、不同习题册的自动排课规则。
- 支持 AI 根据近期反馈生成第二天计划。

## 4. 页面二：排行

### 4.1 页面目标

排行页不是为了制造压力，而是为了让学生看到：

```text
我今天是不是已经打卡？
我在班级里大概处于什么位置？
我连续坚持了多久？
下一枚勋章还差几天？
```

### 4.2 当前显示内容

排行页当前主要显示：

- 当前学生所在班级和个人排名。
- 我的连续学习天数。
- 勋章墙。
- 下一枚勋章目标。
- 今日打卡榜。
- 本周完成榜。
- 连续坚持榜。
- 当自己不在前几名时，支持省略中间排名并展示“我”附近的人。

### 4.3 数据来源

主要接口：

```text
GET /students/{user_id}/rankings
```

主要数据表：

| 数据表 | 用途 |
| --- | --- |
| `student_stats.xlsx` | 连续学习、累计学习、完成率等统计 |
| `student_daily_activity.xlsx` | 每日学习记录和打卡情况 |
| `classes.xlsx` | 班级范围 |
| `users.xlsx` | 班级内同学名称和账号状态 |
| `question_feedbacks.xlsx` | 判断今日是否提交反馈 |
| `focus_sessions.xlsx` | 可用于后续统计专注榜 |

### 4.4 功能实现逻辑

后端逻辑大致是：

1. 找到当前学生所属班级。
2. 读取这个班级所有有效学生的数据。
3. 分别计算三类榜单：
   - 今日打卡榜：按今日打卡或提交速度排序。
   - 本周完成榜：按本周完成天数排序，最多 7 天。
   - 连续坚持榜：按连续学习天数排序。
4. 如果当前学生排名靠后，返回前几名、省略行、当前学生前后一名。
5. 计算勋章墙状态，例如 3 天、7 天、14 天、30 天等。
6. 返回下一枚勋章还差多少天。

前端逻辑大致是：

1. `rank.js` 根据当前选中的榜单类型渲染榜单。
2. `app.js` 监听榜单 tab 点击。
3. 点击今日打卡榜、本周完成榜、连续坚持榜时，只切换 `activeRankBoard`。
4. 不重新请求接口，直接用已有 `activeRankings` 重新渲染。

### 4.5 与其他页面的关系

| 关联页面 | 关系 |
| --- | --- |
| 今日计划 | 学生提交反馈后可能形成今日打卡 |
| 自习室 | 专注时长未来可以纳入排行榜 |
| 曲线 | 连续学习、本周完成等统计也会在曲线中使用 |
| 我的 | 连续学习、今日累计学习在我的页面显示 |

### 4.6 未来升级方向

优先级较高：

- 榜单规则更透明，点击“规则说明”弹出说明。
- 勋章墙做成真实体系，例如早起勋章、连续专注勋章、错题复盘勋章。
- 增加“只和同班同学比”，避免跨层级比较造成挫败。

中长期方向：

- 做成学习激励系统，而不是单纯排名。
- 支持教师端给班级发布挑战。
- 支持周榜、月榜、阶段榜。
- 支持匿名展示，保护学生隐私。

## 5. 页面三：曲线

### 5.1 页面目标

曲线页的核心目标是让学生知道：

```text
我最近学得怎么样？
我哪些章节掌握得弱？
我主要因为什么失分？
下一步最该补什么？
```

它应该成为学生的“学习诊断页”。

### 5.2 当前显示内容

曲线页当前主要显示：

- 数学能力成长曲线区域。
- 目标分数、综合正确率、复错率、本周完成率。
- 最近 14 天学习热力图。
- 累计自习、最高单日、连续学习。
- 章节掌握度。
- 失分原因比例。
- 最该优先补强的内容。

### 5.3 数据来源

主要接口：

```text
GET /students/{user_id}/curve
```

主要数据表：

| 数据表 | 用途 |
| --- | --- |
| `student_daily_activity.xlsx` | 最近 14 天热力图、累计自习、连续学习 |
| `type_mastery_stats.xlsx` | 章节掌握度 |
| `loss_reason_stats.xlsx` | 失分原因比例 |
| `priority_recommendations.xlsx` | 最该优先补强 |
| `question_feedbacks.xlsx` | 后续可用于自动计算掌握度和错因 |
| `question_types.xlsx` | 章节和题型结构 |

### 5.4 功能实现逻辑

后端逻辑大致是：

1. 根据当前日期取前 14 天，不包含今天。
2. 读取学生这 14 天的学习记录。
3. 计算：
   - 14 天累计自习时长。
   - 最高单日学习时长。
   - 从最近一天往前数的连续学习天数。
4. 读取章节掌握度。
5. 如果某个章节没有数据，默认显示 0%。
6. 读取失分原因比例。
7. 如果四类失分原因都是 0%，返回前端显示灰色饼图。
8. 读取最该优先补强内容，通常应该优先选择得分率最低的题型或章节。

前端逻辑大致是：

1. `curve.js` 渲染热力图。
2. `curve.js` 渲染章节掌握度列表。
3. `curve.js` 用 SVG 画失分原因环形图。
4. 占比小于 12% 的错因不在色块上显示百分比，避免拥挤。
5. 所有错因都在饼图下方一行一个展示。

### 5.5 与其他页面的关系

| 关联页面 | 关系 |
| --- | --- |
| 今日计划 | 做题反馈会影响正确率、章节掌握、错因 |
| 自习室 | 专注时间会影响最近 14 天学习热力图 |
| 排行 | 连续学习、本周完成等统计可以共用 |
| 我的 | 今日累计学习、连续学习等个人概览共用 |

### 5.6 未来升级方向

优先级较高：

- 让章节掌握度完全由题目反馈自动计算，而不是主要依赖手工表格。
- 失分原因从“题型层面”细化到“题目层面”。
- 最该优先补强支持点击进入对应题型复习任务。
- 增加趋势解释，例如“本周极限章节提升明显”。

中长期方向：

- 做真正的学习诊断模型。
- 支持教师查看班级共性薄弱点。
- 支持 AI 自动生成个性化复盘建议。
- 支持阶段报告，例如周报、月报、冲刺报告。

## 6. 页面四：自习室

### 6.1 页面目标

自习室页的核心目标是把计划转化成专注行为：

```text
我要专注多久？
这轮做哪个题型？
我今天已经学了多久？
我班里的同学今天专注了多久？
```

### 6.2 当前显示内容

自习室首页当前主要显示：

- 自习室名称。
- 在线人数。
- 安静模式。
- 本轮专注时长选择：30、45、60、自定义。
- 当前任务选择，任务来自今日计划题型。
- 今日数学学习目标，默认 3 小时。
- 已完成专注时长和完成百分比。
- 同桌陪伴，按班级今日专注时长从高到低展示。
- 房间规则。

点击“开始专注”后进入沉浸式专注页面，当前显示：

- 自习室名称和在线人数。
- 当前任务。
- 倒计时。
- 当前时间。
- 本轮专注目标。
- 已完成百分比。
- 暂停/继续。
- 退出专注。
- 白噪音入口的视觉按钮。

### 6.3 数据来源

主要接口：

```text
GET /students/{user_id}/study-room
POST /focus-sessions/start
POST /focus-sessions/{session_id}/pause
POST /focus-sessions/{session_id}/resume
POST /focus-sessions/{session_id}/finish
```

主要数据表：

| 数据表 | 用途 |
| --- | --- |
| `study_rooms.xlsx` | 自习室名称、在线人数等 |
| `study_room_members.xlsx` | 同桌陪伴展示 |
| `student_study_goals.xlsx` | 每日数学学习目标 |
| `focus_sessions.xlsx` | 专注记录 |
| `daily_plans.xlsx` | 当前任务来源 |
| `question_types.xlsx` | 题型名称 |
| `student_daily_activity.xlsx` | 专注完成后可更新每日学习时长 |

### 6.4 功能实现逻辑

自习室首页逻辑大致是：

1. 后端读取当前学生今日计划。
2. 从今日计划里提取可选题型，作为当前任务选项。
3. 读取学生每日数学学习目标，默认 3 小时。
4. 读取学生今日已完成专注时长。
5. 读取同班同学今日专注时长并排序。
6. 前端显示专注时长选择和任务选择。

开始专注逻辑大致是：

1. 学生选择专注时长和当前任务。
2. 前端调用 `/focus-sessions/start`。
3. 后端创建一条专注记录。
4. 前端进入沉浸式专注页面。
5. 前端每秒更新倒计时和进度条。
6. 暂停时调用 `/pause`，继续时调用 `/resume`。
7. 退出专注时调用 `/finish`。
8. 后端结算实际专注秒数，更新专注记录。
9. 前端重新请求自习室数据，回到自习室首页。

### 6.5 与其他页面的关系

| 关联页面 | 关系 |
| --- | --- |
| 今日计划 | 当前任务来自今日计划 |
| 曲线 | 专注时长会进入最近 14 天热力图 |
| 排行 | 后续可以把专注时长纳入榜单或勋章 |
| 我的 | 今日累计学习和每日学习目标会在我的页面展示 |

### 6.6 未来升级方向

优先级较高：

- 专注结束后弹出复盘：本轮是否完成任务、是否遇到难题。
- 白噪音按钮做成真实音频。
- 今日数学学习目标在“我的页面”中可编辑。
- 自定义专注时长做得更像手机滚轮选择器。

中长期方向：

- 支持番茄钟模式、长专注模式、休息提醒。
- 支持多人同桌房间和轻量互动。
- 支持教师查看学生真实专注记录。
- 支持防刷时长策略，例如切后台检测、异常专注识别。

## 7. 页面五：我的

### 7.1 页面目标

我的页面是学生的学习档案页，核心目标是让学生确认：

```text
我是谁？
我属于哪个备考配置？
我的目标院校是什么？
我的每日数学学习目标是多少？
我的学习统计是否正确？
```

### 7.2 当前显示内容

我的页面当前主要显示：

- 学生昵称。
- 数学类型。
- 距考研天数。
- 连续学习天数。
- 今日累计学习小时。
- 我的备考配置：
  - 考试科目。
  - 主选习题册。
  - 备选习题册。
  - 目标院校。
  - 每日数学学习目标。
- 目标院校搜索弹窗。

按照之前需求，当前已去掉：

- 本周完成率卡片。
- 打卡日历。
- 最近学习概览卡片。
- 底部编辑资料、调整目标、更换习题册卡片。

### 7.3 数据来源

主要接口：

```text
GET /students/{user_id}/profile
GET /institutions/search
POST /students/{user_id}/target-school
```

主要数据表：

| 数据表 | 用途 |
| --- | --- |
| `users.xlsx` | 学生昵称、账号信息 |
| `student_profiles.xlsx` | 数学类型、题册、目标院校等 |
| `student_stats.xlsx` | 连续学习、累计学习 |
| `student_study_goals.xlsx` | 每日数学学习目标 |
| `institutions.xlsx` | 院校搜索名单 |

### 7.4 功能实现逻辑

后端逻辑大致是：

1. 根据学生 `user_id` 获取个人档案。
2. 获取学习统计数据。
3. 获取每日数学学习目标。
4. 获取目标院校字段。
5. 如果目标院校为空，前端显示“未选择”。
6. 搜索院校时，从 `institutions` 表按关键词查找。
7. 选择院校后，更新学生档案里的目标院校字段。

前端逻辑大致是：

1. `profile.js` 渲染我的页面。
2. 点击目标院校，打开搜索弹窗。
3. 输入关键词后，`app.js` 延迟 180ms 调用搜索接口，减少频繁请求。
4. 点击某个院校后，调用更新目标院校接口。
5. 更新成功后，重新渲染我的页面。

### 7.5 与其他页面的关系

| --- | --- |
| 今日计划 | 数学类型、题册、班型会影响任务生成 |
| 自习室 | 每日数学学习目标和今日累计学习共用 |
| 曲线 | 连续学习、累计学习等统计共用 |

### 7.6 未来升级方向

优先级较高：

- 每日数学学习目标支持在我的页面修改。
- 目标院校选择后，支持目标分、专业、考试科目联动。
- 习题册配置支持编辑，但需要权限控制，避免学生乱改影响计划。

中长期方向：

- 做完整学习档案，包括入班时间、阶段目标、老师备注。
- 做账号设置和隐私设置。
- 做学习报告入口。
- 做支付/续费/服务到期提醒入口。

## 8. 五个页面之间最重要的业务闭环

当前最核心的闭环是：

```text
我的页面确定学生身份和配置
  ↓
今日计划根据配置和进度生成任务
  ↓
自习室围绕今日任务记录真实学习时间
  ↓
今日计划提交做题反馈
  ↓
曲线页根据反馈和学习记录诊断薄弱点
  ↓
排行页用完成、打卡、坚持激励学生继续
  ↓
第二天今日计划继续按进度向后布置
```

这条线如果跑通，网站就从“静态展示”变成了“真正能督学”的产品。

## 9. 当前阶段最值得优先完善的方向

### 9.1 第一优先级：数据闭环更真实

当前已经有数据库和 API，但后续最重要的是让这些数据更自动：

- 提交反馈后自动更新题型掌握度。
- 提交反馈后自动更新章节掌握度。
- 专注结束后自动更新每日学习记录。
- 今日完成后自动推动 `student_progress` 指针。
- 最该优先补强由真实得分率自动生成。

### 9.2 第二优先级：管理后台

未来上万人使用时，不应该一直手动改 Excel。

需要逐步做：

- 学生管理后台。
- 班级管理后台。
- 题型/题目管理后台。
- 每日计划查看和人工调整后台。
- 反馈数据查看后台。

### 9.3 第三优先级：正式前端工程化

当前原生 HTML/CSS/JS 适合 MVP，但页面和交互继续变复杂后，可以考虑：

- 使用 Vue 或 React 拆成组件。
- 使用路由管理五个页面。
- 使用状态管理保存当前学生数据。
- 使用前端构建工具压缩资源。
- 增加真实移动端适配测试。

### 9.4 第四优先级：权限和安全

如果面向真实用户，必须补：

- 密码加密存储。
- 登录 token。
- 学生只能访问自己的数据。
- 教师端和学生端权限隔离。
- API 防止越权访问。
- 数据备份和恢复。

## 10. 后续修改页面时的建议顺序

每次要改某个页面，建议按这个顺序：

1. 先写清楚这个页面要解决什么学生问题。
2. 确认需要哪些数据。
3. 看现有 API 是否已经返回这些数据。
4. 如果没有，先改数据表和后端接口。
5. 再改对应页面 JS。
6. 最后改 CSS，让页面好看。
7. 跑验证脚本。
8. 更新本文档。

不要一上来只改视觉，因为视觉改完后，如果数据逻辑不清楚，后面容易推倒重做。
